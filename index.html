Sunset and sunrise times API (Version 2)

Download OpenAPI specification:

License: MIT Terms of Service

Our free API tells you when the sun rises and sets anywhere on Earth, plus twilight, golden hour, solar position and moon data. All you need is a latitude and longitude; you make a simple GET request and get the answer as JSON.

Time come in the local timezone of the place, and you can ask for a single day or up to a whole year in one request.

The API is free to use; no sign up or API key required.

https://sunrise-sunset.org/api

Get sunrise, sunset, twilight, and moon data for a location

Returns when the sun rises and sets anywhere on Earth, plus twilight, golden hour, solar position and moon data.

query Parameters
lat
required
number <float> [ -90 .. 90 ]
Example: lat=36.72016

Latitude in decimal degrees, -90 to 90.

lng
required
number <float> [ -180 .. 180 ]
Example: lng=4.42034

Longitude in decimal degrees, -180 to 180.

date
string
Example: date=tomorrow

Date in YYYY-MM-DD format, today or tomorrow. Defaults to today in the local timezone of the coordinates.

date_start
string <date>
Example: date_start=2026-01-01

Start date in YYYY-MM-DD format, paired with date_end, the requested date range cannot exceed 366 days in a single request. You can request days up to a full year in the same location once instead of one request per day.

date_end
string <date>
Example: date_end=2026-12-31

End date in YYYY-MM-DD format, paired with date_start, the requested date range cannot exceed 366 days in a single request. You can request days up to a full year in the same location once instead of one request per day.

tz
string
Example: tz=Europe/Madrid

Timezone of the location. You usually don't need this as the default time comes in the location's time zone. Set it if only you want the times expressed in a different time zone, using a standard time zone name, such as Europe/Madrid or America/Los_Angeles (abbreviations like PST are rejected).

Coordinates in international waters resolves to nautical etc/GMT zones.

time_format
string
Default: "iso8601"
Enum: "iso8601" "unix"
Example: time_format=iso8601

The time format of events. By default, the response would be in iso8601, but you can use unix. If unix, all event times are Unix epoch seconds (UTC by definition, handy for embedded clients). tzid/utc_offset are still included as context in the response, and the date/tz parameters still determine which local calendar day is computed. Events that do not occur stay null.
